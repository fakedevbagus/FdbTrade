## Outcome

R1.3 adds an authenticated, projection-only research workbench over the R1.2
API. An operator can choose a quality-eligible registered R0.6 dataset,
explicitly submit the single frozen baseline, reopen the deterministic list and
detail projections, and distinguish succeeded, blocked, failed, pending, and
running lifecycle evidence.

## Observable workflow

- `/research/workbench` reads the R1.2 list and selected detail with the local
  private session and no cache.
- Only accepted datasets with zero quarantined, gap, and duplicate observations
  appear in the submission selector. Stored historical staleness does not make
  an otherwise accepted replay dataset ineligible.
- The browser sends exactly `datasetId` and a canonical millisecond UTC
  `createdAtUtc` through same-origin POST `/api/research/runs`.
- The workbench displays lifecycle timestamps and attempts, failure/block
  reasons, the complete metrics set, explicit realistic costs, dataset/config/
  rule hashes, result and summary hashes, engine identity, and artifact size.
- Duplicate submission truthfully reports that the existing durable run was
  reopened. Empty, loading, quality-blocked, failed, stale-session,
  malformed-response, and backend-unavailable states do not invent green data.
