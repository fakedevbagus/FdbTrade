## Outcome

R0.3 establishes one bounded path for the pinned install and all four repository
verification stages:

```text
make toolchain-gate
  -> Corepack pnpm@11.22.0 + frozen install
  -> lint
  -> typecheck
  -> test
  -> build
```

`scripts/rebuild_toolchain.py` is the authority for that path. It uses explicit
timeouts, package-local binaries, serial Vitest workers, bounded output tails,
atomic JSON reports, and a cache/store rooted at
`artifacts/toolchain/cache`. Corepack, pnpm, npm, and XDG caches no longer
depend on the operator home directory.

The root package scripts, Makefile, local clean-room runner, bootstrap, operator
CLI, and GitHub Actions now converge on this toolchain. CI is one required
blocking job and preserves `artifacts/toolchain/gate.json` even when the gate
blocks.

## Preflight and failure semantics

`scripts/fdbtrade preflight --json` now keeps stdout as valid JSON and catches
socket creation/connect restrictions. In a restricted environment each port is
reported as `probe_unavailable` with a warning rather than raising a traceback.
All version probes are bounded. The pnpm probe uses the same isolated Corepack
path as the main runner.

The runner distinguishes `pass`, `fail`, `timeout`, `environment_blocked`,
`skipped`, and `planned`. A zero-exit test process with a non-zero skip count is
classified `skipped`; skipped, timeout, blocked, and failed results all make the
aggregate gate non-PASS. Every result records its command, cwd, timeout, exit
code, duration, output tails, and first actionable failure.

## External-state incident

During an exploratory full-suite run, the legacy tests detected an
already-running `fdbtrade-postgres` container. Before the R0.3 guard existed,
they executed the PostgreSQL migration rollback/reapply and auth test-user/session
lifecycle. The migration test ended with both legacy migrations applied. No
container was started by R0.3, but that diagnostic did mutate external database
state and violated the intended R0.3 boundary.

No destructive cleanup was attempted because the exact pre-run database state
was not known. The incident is recorded in the JSON evidence. The final runner
sets `FDB_TOOLCHAIN_EXTERNAL_STATE=disabled`; both database-mutating lifecycle
classes skip before inspecting Docker or the database, and their skip blocks a
green gate. The final gate did not mutate external database state.

## Test-harness repairs

- ESM package identity was made explicit so TypeScript Vitest configs no longer
  load as CommonJS.
- Generated toolchain artifacts are pruned from legacy source scans.
- The old startup test selects an available local port instead of assuming port
  3000 is unused by unrelated host services.
- Nested install/lint/typecheck/build execution was removed from the Python test
  stage. It validates bounded plans while the outer gate performs each real
  stage exactly once.
- R0.3 behavior tests cover cache isolation, non-mutating dry-run, timeout and
  failure classification, skip classification, socket-restricted preflight,
  pinned package-manager shape, and Make/CI wiring.

## Remaining blocker and warnings

The gate cannot be green while the legacy PostgreSQL lifecycle tests remain a
required part of discovery but are forbidden from mutating external state.
That is intentional evidence for R0.4, not a hidden success. R0.4 must replace
the PostgreSQL authority with the authorized SQLite foundation and define a
hermetic lifecycle test path.

Non-blocking warnings remain:

- contracts ESLint inherits React/pages assumptions that do not match a library
  package;
- frontend Next build warns that the `middleware` convention is deprecated;
- sqlite3 CLI is absent, while Python provides sqlite3 3.45.1.

These are recorded and not repaired as product/runtime work in R0.3.
