## Executive summary

The repository contains a substantial body of deterministic domain logic, but
it is not an operational trading-intelligence system at the breadth claimed by
the legacy milestone reports. Focused behavior tests passed for the runtime
core, signal stack, fixture/historical/backtest path, risk/paper contracts, and
frontend views. Those results make much of the pure logic salvageable.

No subsystem is classified `KEEP`. The deciding gaps are production wiring,
durable authority, target SQLite fit, measured/calibrated evidence, or an
executable full gate. Passing isolated tests does not establish those
properties.

The most consequential findings are:

- `startRuntimeScheduler` has no production importer. Its production-shaped
  builder uses in-memory locks, checkpoints, dedupe and completion ledgers, and
  its handlers only record observations.
- PostgreSQL remains the only implemented auth/session store. Redis is a
  configuration/documentation remnant. SQLite is only detected; it has no
  application schema, migration or runtime adapter.
- The user-visible signal flow is a deterministic, fixture-only 1h projection.
  Feature snapshots, decisions, alerts, calibration outcomes and risk state are
  not durable authorities.
- Paper broker, risk, analytics, broker/demo/live, research and advanced-alpha
  code is principally isolated contract logic. It is not equivalent to an
  operational service.
- Backup and restore scripts can report success without backing up or restoring
  a database. This is a critical operational contradiction.
- The quarantined M48 directory is not a provider implementation. In
  particular, `provider.ts` ends after an in-memory quota counter and contains
  no `ShadowMarketDataProvider`. The directory has no tests, production import,
  configuration template, or ADR-0037.

Classification totals for the 31 repository subsystems are 20 `REPAIR`, 8
`REPLACE`, 1 `DELETE`, 2 `ARCHIVE`, and 0 `KEEP`. The ten M48 files add 4
`REPAIR` and 6 `REPLACE`. The machine-readable source of record is
`artifacts/rebuild/r0.2/capability-audit.json`.

## M48 security audit

M48 remains `unreviewed_not_authoritative`. No M48 file was modified, no
credential was read, and no network request was made.

| File | Class | Finding |
|---|---|---|
| `spec.ts` | REPAIR | Strict schema and exact HTTPS origin shape are useful; private/loopback/resolved addresses are not controlled and extra timeframe mappings are allowed. |
| `allowlist.ts` | REPAIR | GET/origin/path/query-name controls are useful; defense-in-depth does not re-derive exact templated query values and cannot address DNS SSRF. |
| `secrets.ts` | REPLACE | `lstat` occurs before existence handling, stat/read is TOCTOU-prone, parent symlinks are unchecked, and there is no descriptor-based no-follow read. |
| `fsPort.ts` | REPLACE | Path-based stat/read/append/write cannot provide safe no-follow reads or atomic owner-only audit writes. |
| `audit.ts` | REPLACE | Contains `/* __PART2__ */`; reads the whole sink before bounding, follows path writes, lacks atomicity/mode/integrity, and weakly validates records. |
| `gate.ts` | REPLACE | Claims never to throw but missing paths can throw at `lstat`; lexical repository check ignores real paths/parent symlinks; terms mode/owner is unchecked. |
| `transport.ts` | REPLACE | Redirects are refused, but DNS/private-target policy is absent and `response.text()` buffers the body before the size check. Character count is not byte count. |
| `provider.ts` | REPLACE | No provider class or mapping/request execution exists; only constants, error types and a process-local quota counter. |
| `mockTransport.ts` | REPAIR | Useful deterministic FIFO mock, but untested and unable to prove absent provider behavior; it records full URLs. |
| `sanitize.ts` | REPAIR | Useful control-character collapse/digests; it is not secret redaction and its universal-use claim is unproved. |

Cross-cutting conclusions:

- Secret leakage: no intentional raw-secret persistence was found, but stable
  code-only error discipline is not enforced by types or tests. A sanitizer
  cannot remove a secret that a caller passes accidentally.
- SSRF and redirects: `redirect: "error"` is a sound intention. It does not
  handle private/link-local/loopback IPs, DNS rebinding, or post-resolution
  address verification.
- Filesystem boundary: leaf symlink checks do not close parent-symlink or
  time-of-check/time-of-use races. `realpathSync` exists in the port but is not
  used by the gate or secret loader.
- Permissions: only the directory and credential file are partially checked.
  Terms/spec/audit ownership, safe creation, mode, atomic replace and fsync are
  not established.
- Raw payloads: audit intends digest-only persistence, but there is no provider
  to prove the rule and transport buffers the complete response before its
  post-read cap.
- Quota, duplicates and staleness: quota is process-local and resets on
  restart; duplicate/staleness behavior exists only as comments/constants and
  reason-code types because the provider is missing.
- Fallback: comments prohibit fixture substitution, but there is no integration
  path whose failure behavior can be tested.

## Critical contradictions and risks

1. `PHASE2_PROGRESS_MANIFEST.json` says every gate exited zero with large test
   totals. Today pnpm fails, every full suite times out, typechecks time out,
   and preflight crashes. The manifest was deliberately not edited in R0.2.
2. Runtime comments use “durable” and “restart-neutral”, but production-shaped
   stores are new in-memory objects and no application entrypoint starts them.
3. Phase 2 architecture names Redis as persistence. No Redis service or client
   exists.
4. Loopback-only is asserted in docs while local Next commands omit a host flag
   and the environment template declares `0.0.0.0`.
5. `provider.ts` describes a complete credentialed provider that is not in the
   file. This is the sharpest M48 claim/behavior mismatch.
6. Backup creates a placeholder gzip when no database tool is available and
   reports success. Restore similarly reports completion after only validating
   structure. Neither is recovery evidence.
7. Dashboard calibration uses no outcomes, costs are placeholders, correlation
   penalty is empty, and portfolio heat is `null`, but the UI exposes the
   finished vocabulary.
8. A tracked file named `=` is an old Python traceback, demonstrating that the
   repository tree contains accidental execution output.

## Salvage map

The following foundations should be preserved as source material while their
authority and wiring are rebuilt:

- Canonical zod contracts, UTC/timeframe utilities, stable serialization and
  content-derived identifiers.
- Fixture provider, normalizer/quality checks, CSV parser and immutable
  historical replay semantics.
- Indicator and market-structure pure functions.
- Regime, four baseline strategies, ensemble, ranking and edge-gate pure logic,
  while retaining their placeholder/unvalidated labels.
- Event-driven backtest engine, deterministic fills/metrics and golden fixtures.
- Research split/purge/stress/promotion primitives.
- Risk formulas and paper ledger/reconciliation state-machine contracts.
- Frontend fail-closed fetch validation and presentational components.
- Focused behavior tests and Python mirrors as regression material—not as
  production authority.

The following should not be carried forward as authority:

- PostgreSQL/Redis/Docker assumptions after SQLite cutover.
- In-memory scheduler, alert, observability, risk-state and paper-state stores.
- Placeholder-success backup/restore and deployment claims.
- Legacy milestone completion reports and test totals.
- M48 wiring or security claims.
- The tracked `=` traceback artifact.

## R0.3 environment blockers

- Corepack/pnpm attempts to create a cache directory under a read-only home and
  exits with `EROFS`.
- Package-local binaries work for focused tests, but all three direct
  typechecks exceeded 45 seconds and full suites exceeded 60 seconds.
- `scripts/fdbtrade preflight --json` does not catch socket-creation failure;
  it exits 1 with a traceback instead of machine-readable JSON in this sandbox.
- Vitest warns that each TypeScript config uses ESM syntax while being loaded as
  CommonJS under the future native config loader.
- The live PostgreSQL auth/database tests are environment-skipped. R0.3 must
  preserve that truth rather than converting the skip to a pass.
