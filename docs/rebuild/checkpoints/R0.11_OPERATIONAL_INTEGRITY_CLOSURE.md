## Outcome

R0.11 closes R0.10 crash-consistency and evidence-coverage gaps without a new
migration or new product authority. Backup and restore now publish only fully
verified and fsynced staging trees through atomic directory rename. SQLite
remains the only mutable durable metadata authority; published directories are
immutable recovery evidence.

## Backup publication

The online SQLite snapshot is normalized and checked against the exact active
nine-migration ledger. The artifact set is read from that completed snapshot,
then both R0.6 market-data and R0.8 research bytes are copied to a staging
directory on the output filesystem. Manifest schema version 2 fixes exact
fields, paths, artifact authorities, literal-false safety flags and SHA-256's
integrity-only meaning.

Verification occurs while the directory is still staged. The database,
artifacts, manifest, artifact-directory chain, staging directory and output
parent are fsynced before rename; the output parent is fsynced again after
rename. Only then is `backup_created` appended. A post-rename/pre-event fault
therefore leaves a valid but explicitly unclaimed backup rather than invented
SQLite evidence.

## Restore publication

The backup is strictly verified before target mutation. The target is absolute
and must be absent or a real empty directory with no symlink component. Restore
is assembled in a sibling staging root, verifies integrity, foreign keys,
exact migrations and all artifacts, appends `restore_verified`, checkpoints
and closes SQLite, then fsyncs every file and directory before atomic rename.
Non-empty targets and partial publication fail closed.

R0.10 version-1 manifests remain readable under their exact old schema. This
is format compatibility and SHA-256 integrity evidence only; R0.10 publication
is not retroactively described as crash-durable. Known R0.10 SQLite sidecars
are ignored legacy residue and are never trusted or restored.
