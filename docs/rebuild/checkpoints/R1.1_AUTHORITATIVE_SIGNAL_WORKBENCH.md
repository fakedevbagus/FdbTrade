## Outcome

R1.1 gives the authenticated local operator one workbench for selecting an
existing R0.6 dataset, invoking the existing R0.12 POST and reopening durable
R0.7 evaluation/candidate evidence from SQLite. Candidate, wait, blocked and
failed are explicit states with dataset, artifact, frozen-rule and UTC lineage.
The legacy fixture scanner is neither called nor presented as authority.

## Read projection

- `GET /api/signals/evaluations` returns registered R0.6 datasets plus the
  newest 100 R0.7 runs in deterministic descending order.
- `GET /api/signals/evaluations/{runId}` returns one canonical run detail.
- Both routes require the private session and reject query extensions; detail
  identities are restricted to canonical `sir_` values.
- The adapter performs SELECT/read-only projection. It does not recover work,
  evaluate datasets or advance candidate lifecycle.
- Terminal evidence is hash-checked and reconciled with rule, dataset,
  candidate, lifecycle and immutable R0.6 artifact lineage. Failed runs remain
  inspectable even when missing/corrupt artifact input caused the failure.

## Operator UI

`/signals/workbench` lists registered datasets and durable evaluations, submits
only the selected dataset identity and its recorded assessment instant to the
existing R0.12 endpoint, and displays full detail or truthful empty/error
states. The browser uses a bounded same-origin facade; backend authentication,
strict schema validation and SQLite remain authoritative. The UI cannot edit
the rule, create a candidate, or fall back to scanner fixtures.

## Preservation and boundaries

- No migration was added; the ledger remains nine ordered migrations through
  `0009_operational_hardening`.
- R0.6 artifact and R0.7 signal semantics are unchanged. Identical requests
  replay the existing run without duplicate evidence or candidate rows.
- R0.8 research and R0.9 risk/paper tables are not mutated.
- Scheduling, provider selection/network access, M48, model promotion,
  automatic paper and demo/live/provider-order execution remain off.
- All ten M48 files remain byte-identical: 55,941 bytes and aggregate manifest
  digest `f7dc5aacade5078cf934be760651c2e59d9e340c7a096a25629006d8f8555fe6`.
