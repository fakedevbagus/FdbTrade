## Outcome

R1.2 exposes the existing R0.8 `ResearchBacktestAuthority` through authenticated
strict POST/list/detail routes. The operator can submit one registered R0.6
dataset to the frozen baseline, replay the same durable identity, and reopen
SQLite plus immutable artifact evidence after a process restart. The legacy
backtest route remains separate and non-authoritative.

## API boundary

- `POST /api/research/runs` accepts only `datasetId` and canonical
  millisecond-precision `createdAtUtc`.
- Before execution it registers or verifies the frozen rule/config, recovers
  interrupted R0.8 work and blocks if registered evidence is corrupt.
- `GET /api/research/runs` returns registered datasets plus at most 100 runs in
  deterministic `createdAtUtc desc, authorityRunId desc` order.
- `GET /api/research/runs/{id}` accepts only canonical `rbr_` identities.
- Both GET paths verify terminal artifact bytes, metadata, summary, manifest,
  dataset provenance, config lineage and deterministic request identity.

- R0.7 evaluation/candidate/evidence and R0.9 risk/paper/fill/outcome tables are
