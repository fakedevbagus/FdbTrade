## Outcome

R0.8 makes SQLite authoritative for the immutable baseline research
configuration, backtest run lifecycle and result metadata. Successful and
quality-blocked evidence is stored as immutable SHA-256-addressed artifacts
below `FDB_DATA_ROOT`. The authority reopens every input through R0.6 and uses
the exact registered R0.7 rule lineage through a shared pure evaluator.

## Research configuration and provenance

The initial registered configuration is `baseline-historical-evaluation`
version `1.0.0`. It records initial equity, fixed research quantity, warmup,
seed, one-bar latency and explicit realistic fill costs. Its SQLite row has a
foreign key to `authoritative-momentum-baseline` logic/config `1.0.0` and a
digest that covers both research assumptions and the frozen signal-rule
configuration.

Each run is bound to one R0.6 dataset id and artifact digest. Dataset bytes are
re-hashed and parsed before use. Only accepted quality with no quarantine, gaps
or duplicates can execute. Historical freshness is not treated as current-feed
freshness; the immutable dataset period is the explicit replay boundary.

## Result evidence and interpretation

A successful result contains the complete engine result, full manifest,
metrics, cost assumptions, subject lineage, source dataset identity and config
digest. A quality rejection produces a durable `blocked` artifact with reasons
and null metrics. Artifacts are written and fsynced before SQLite publication;
the result row pins their SHA-256, byte count and summary digest.

The evidence explicitly says that it is historical only, does not calibrate
signal confidence, has no confidence value, is not eligible for model promotion
and is not operational outcome authority. Historical replay does not insert
R0.7 signal candidates or lifecycle events.

## Recovery and idempotency

Logical run identity covers dataset plus registered research configuration.
Interrupted `running` rows return to `pending`; a published but uncommitted blob
is reported as an orphan and deterministically reused on replay. A response lost
after the terminal transaction reopens the same result rather than creating a
second run. Recovery re-verifies artifact bytes, summary digest, engine
manifest and source dataset provenance, and reports corruption fail-closed.
