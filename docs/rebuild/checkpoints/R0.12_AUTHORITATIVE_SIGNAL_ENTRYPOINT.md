## Outcome

R0.12 adds one authenticated production entry point for the existing R0.7
signal authority. An operator can submit a registered R0.6 dataset id and an
explicit UTC assessment instant to receive durable candidate, wait, blocked or
failed evidence. The route contains no signal logic of its own and never uses
the legacy fixture scanner as authority.

## Durable route behavior

The route uses the canonical application SQLite connection, the R0.6
content-addressed artifact root and `SignalIntelligenceAuthority`. It verifies
that the dataset is registered, idempotently verifies the frozen baseline rule,
runs R0.7 recovery and refuses to continue if recovery finds corrupt evidence.
Identical requests replay the original run without duplicating evidence or a
candidate.

File-backed route behavior proves candidate persistence across close/reopen,
explained wait, durable quality blocking and recovery of an interrupted
evaluation. Malformed, extended, unauthenticated and unknown-dataset requests
fail before an evaluation run is created.

## Preserved boundaries

- SQLite remains the only mutable durable metadata authority; no migration was
  added and count/order remain nine through `0009_operational_hardening`.
- R0.6 artifacts remain immutable and content-addressed. Universe remains
  EURUSD, GBPUSD, USDJPY, USDCHF, AUDUSD, USDCAD and NZDUSD; timeframes remain
  15m, 1h and 4h.
- R0.7 rule/evidence/candidate/lifecycle semantics remain binding. R0.8
  research and R0.9 risk/paper/outcome tables are not mutated by the route.
- Persisted risk approval remains mandatory before paper execution. Kill stays
  durable and latched; release lands in red.
- The scheduler remains observation-only and off by default. The R0.10 UI
  remains a projection and gains no mutation surface.
- Live execution, provider-order transport, credentialed/network providers,
  model promotion and M48 remain disconnected. SHA-256 remains integrity
  evidence, not cryptographic authenticity.
