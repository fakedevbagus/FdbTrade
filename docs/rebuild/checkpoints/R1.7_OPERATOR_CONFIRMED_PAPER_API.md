## Outcome

unchanged R0.9 risk, ledger, reconciliation and outcome authority. One POST
with the literal `confirm-paper-run` is the explicit operator confirmation.
Only an R1.6 verified resolution identity and positive quantity enter R0.9.

## Observable behavior

- POST rejects missing confirmation, unknown fields, query parameters,
  arbitrary cost/conversion fields and unauthenticated requests.
- R1.6 recovery and verification run before R0.9 recovery, reconciliation and
  new work.
- Identical replay reopens one durable run without duplicate decisions,
  orders, fills or outcomes; divergent replay fails with conflict.
- Approved, rejected, blocked and failed outcomes are projected truthfully.
  A killed risk state persists a rejected decision and creates no fills.
- GET list/detail expose durable runs only and perform no paper submission.
- Restart recovery resumes interrupted work; corrupt or tampered resolution
  and ledger evidence fail closed.
